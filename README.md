# 🖥️ 逐声计划 · 内容组协作管理系统（组员端 + 组长端）

> 为广播剧字幕整理内容组开发的**纯本地、不联网的双端命令行工具**：组员端覆盖"信息收集 → 重点剧集审核 → 10% 人工抽检 → 技术组兜底"四个阶段的任务认领、DDL 提醒与文件规范命名；组长端负责成员管理、数据校验清洗、错误整改闭环和 matplotlib 可视化监控仪表盘。组员无需安装 Python，打包为约 113 MB 的独立 exe 双击即用。
>
> 关键词：`Python` `pandas` `matplotlib` `CLI 交互程序` `本地 JSON 持久化` `PyInstaller 打包分发` `任务流管理` `数据校验`

---

## 一、项目背景 & 目标

内容组有数十名志愿者协同整理广播剧资料，每部剧要经历四类工作：

1. **信息收集**——收集每集的片名、URL、非常驻角色、有无其他配音演员；
2. **重点剧集审核**——人工审核"有其他配音演员"的剧集；
3. **人工抽检复核**——按 10% 比例抽检；
4. **技术组兜底**——技术组爬不出来的剧集，由信息表下发给内容组人工处理。

协作中存在四个痛点：任务靠口头分配容易重复或遗漏、文件命名五花八门无法交接、DDL 靠群通知、组长无法掌握整体进度与质量。本系统用两套程序解决（因组员环境不保证联网、不保证装 Python，故设计为**双程序 + 本地 JSON 存档 + exe 分发**）：

| 角色 | 程序 | 核心职责 |
|---|---|---|
| 组员 | 内容组组员专用.py / .exe | 认领任务、查进度与 DDL、提交文件自动规范命名 |
| 组长 | 内容组组长专用.py | 发 ID/圈名、设 DDL、清洗校验、监控报告、移交技术组 |

## 三、数据契约（程序读写的文件）

### 1. 任务表 Excel（组长下发，组员保存在程序同目录）

四阶段对应四张表，结构统一：**第 1 行每两列一个任务（任务名在偶数列），第 2 行为"名称 / ddl"表头，第 3 行起左列填剧集名、右列填该任务 DDL**。一人可绑定多列（认领多个任务）。

| 阶段 | 任务表 | 待检查文件夹 | 提交格式 | 命名前缀/后缀 |
|---|---|---|---|---|
| 信息收集 | 广播剧剧集.xlsx | 信息待检查文件夹 | `.csv` | `任务名_…`（按**任务名**匹配） |
| 重点剧集审核 | 审核表.xlsx | 审核待检查文件夹 | `.txt` | 前缀`审核`（按**剧集名**匹配） |
| 人工抽检复核 | 抽检表.xlsx | 抽检待检查文件夹 | `.txt` | 前缀`抽检` |
| 兜底阶段 | 需人工转接.xlsx | 需人工转接待检查文件夹 | `.txt` | 前缀`抽检` |

仓库内 [数据库/审核表.xlsx](数据库/审核表.xlsx) 是真实样例：任务《LASER出道日》，含 **45 个剧集名**，DDL 示例 `2026-11-25 00:00:00`。

### 2. 程序自动生成的存档文件

| 文件 | 端 | 内容 |
|---|---|---|
| `member_config.json` | 组员 | 圈名（cn）与四阶段已认领任务、DDL、已提交数/总数 |
| `member_list.json` | 组长 | 8 位随机数字 ID → 组员姓名映射 |
| `settings.json` | 组长 | 各广播剧 DDL 配置 |
| `【剧名】错误处理表.xlsx` | 组长 | 清洗出的错误清单，含"是否已修正（请打√）"列 |
| `【剧名】全部通过.txt` | 组长 | 无错误时生成的通过标记 |
| `可移交技术组列表.txt` | 组长 | 全部整改完成的剧名单 |
| `组长监控综合图表.png` / `…报告.txt` | 组长 | 可视化仪表盘与文字报告 |

### 3. 规范命名格式

```text
信息收集：任务名_圈名_提交日期(YYYYMMDD)_V版本号.csv
其他阶段：前缀+剧集名_圈名_提交日期_V版本号.txt
例：第一期：新队友_小林_20260406_V2.txt
```

## 四、组员端功能（内容组组员专用.py，560 行）

首次启动输入**圈名**并二次确认（确认后不可更改，与本机程序永久绑定），之后进入四阶段主菜单；每个阶段提供 3 个操作：

1. **认领任务**——程序解析任务表列出可认领任务，输入认领数量（多任务时需输入 `OK` 二次确认，`q` 退出与组长协商）；任务名做**标准化模糊匹配**（去除空格/标点、全角半角与中英文标点归一、转大写、仅保留中英文与数字，双向包含即命中），并实时查重防止同一任务重复认领；认领时自动绑定该任务 DDL；
2. **查询进度与 DDL**——信息收集阶段按任务数统计（已提交/未提交），其他阶段按剧集数统计（已提交 x / 共 y / 剩余 z），并显示 DDL 与剩余天数（兼容 `YYYY-MM-DD HH:MM:SS`、`YYYY/MM/DD` 两种格式，逾期显式标注）；
3. **文件命名规范化**——扫描待检查文件夹中的 `.txt/.csv`，仅匹配本人已认领任务范围内的任务名/剧集名，自动改名为规范格式、按版本号覆盖同名旧文件，并把提交数回写到本地存档；匹配失败时打印清洗后的关键词供排查。

**DDL 主动提醒**：再次打开程序时，若名下有任务距 DDL ≤ 4 天，欢迎语自动附带预警。

## 五、组长端功能（内容组组长专用.py，492 行）

组长功能受**密钥保护**（源码配置区硬编码的 8 位组长密钥，使用前请修改），主菜单 5 项：

| # | 功能 | 说明 |
|---|---|---|
| 1 | 组员文件规范化 | 校验 8 位 ID → 读广播剧列表匹配剧集 → 规范命名（兼容旧 ID 体系的入口） |
| 2 | 监控综合报告 | 生成四合一图表 + 文字报告（核心功能，见下） |
| 3 | 数据清洗 | 逐文件校验、出错误表、整改后自动列入移交 |
| 4 | 生成组员 ID | 输入组员姓名，批量生成随机 8 位 ID 并落盘 |
| 5 | 设置 DDL | 按 `YYYY-MM-DD HH:MM` 为每部剧设置截止时间 |

**数据清洗规则**：每份提交文件至少 4 行非空内容，依次校验——第 2 行必须以 `http://`/`https://` 开头且长度 ≥ 10（URL）、第 3 行（非常驻角色）与第 4 行（其他配音演员）非空。有错误则生成错误处理表（文件名 / 收集人 / 错误原因 / 是否已修正列），组长直接在 Excel 里打 `√`（兼容 `v/V/✓`），下次运行监控时自动识别整改进度；全部打勾或本就无错误的剧自动写入"可移交技术组列表"。

**监控仪表盘**（matplotlib 2×2 四合一，SimHei/微软雅黑中文字体）：

1. 个人提交数量柱状图；
2. 整体进度饼图（规范文件数 / 剧集总数）；
3. 个人准确率柱状图（以"全部通过"或"错误表全部打勾"的剧为已清洗口径）；
4. 各剧 DDL 剩余时间柱状图，逾期红色加粗标注、24 小时内橙色预警。

文字报告另含**个性化提醒**：零提交、提交量低于组员均值一半、准确率低于 80% 的组员会被点名；控制台同时输出精简版仪表盘便于快速查看。

## 六、运行与分发

**开发/源码运行**：把任务表放到脚本同目录后执行：

```bash
python 内容组组员专用.py   # 组员端
python 内容组组长专用.py   # 组长端
```

**组员分发**：`最终结果/内容组组员专用.zip` 内含独立 exe（约 113 MB，免安装 Python）与使用说明，解压后双击 exe，按提示把任务表和待处理文件放到对应目录即可；主菜单输入 `0` 正常退出。

完整的组长操作顺序（建目录 → 发 ID → 设 DDL → 组员提交 → 清洗 → Excel 打勾整改 → 监控报告 → 移交）见 [代码/程序组长使用说明.txt](代码/程序组长使用说明.txt)；需求与交互细则的完整设计文档见 [代码/组员程序设计说明.txt](代码/组员程序设计说明.txt)。

## 八、注意事项与版本差异（如实说明）

- **两端身份体系不同步**：组员端源码为较新的**圈名（cn）+ `member_config.json`** 四阶段版本；组长端仍使用较早的 **8 位 ID + `member_list.json`** 与 `广播剧列表.xlsx` 契约，其功能 1 是旧版组员入口。实际部署时组长端的 ID 管理与新版组员端尚未打通，两套 JSON 不通用；
- **随附说明文档对应旧版**：两份"使用说明"txt 描述的是 8 位 ID、单文件夹（待检查文件）的旧版交互，与新版组员源码的圈名、四阶段菜单存在差异，以源码和"组员程序设计说明.txt"为准；
- **路径约定**：程序以运行目录（`Path.cwd()`）为基准读写所有文件，任务表必须放在程序同目录；从 exe 启动时即 exe 所在目录；
- **安全**：组长密钥硬编码在源码中，仅适合内部小范围使用，正式分发前应修改；
- 组员端重命名采用"先删同名目标文件再改名"的覆盖策略，运行前请确认待检查文件夹中没有需要保留的同名旧版文件；处理完应按提示把文件移出待检查文件夹，避免重复处理。

> 📌 技术要点小结：这个项目的价值在于把一套**真实的多人协作流程工程化**——用双列结构的 Excel 作为组长与程序之间的"低代码配置接口"（非技术组长改表即可派活），用 JSON 本地存档实现无网络环境下的认领/进度状态机，用"错误表打勾→监控自动识别→移交列表"形成质量整改闭环；命名匹配上用标点归一 + 双向包含容忍组员不规范的文件名，仪表盘把提交量、准确率、DDL 三类管理指标一次出图。两端版本契约不统一是它当前最主要的工程债，也是后续迭代（统一身份体系、合并为单程序）的明确方向。
